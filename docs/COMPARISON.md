# How it compares

says less than the table needs, the cell says so. The last column is what sets the map apart or what it lacks;
several of these tools are complementary rather than rivals.

## What the map does differently

- **The meaning is written by people, per block, and checked by a tool.** Most of the tools above say *what* is
  there (symbols, files, imports, signatures). Some carry what people write: an instructions file, Doxygen's
  comment blocks, a description per file taken from header comments or docstrings (agentmap by remorses), or one
  per directory (context-map). A tag says *what a block is for* ("the totals: each line's amount and discount, the
  coupon on the rest"), which is what an agent searches by when it starts a task. The tool keeps the tags honest:
  every code file tagged, a purpose of three words or more, ids unique per file, blocks under 16,000 characters,
  recipes that name only blocks that still exist, and the map current, all failing CI when not.
- **On demand, in rounds, not in every prompt.** Aider's map and an instructions file go into every request; a
  packed repository goes in whole; codemap and agentmap (remorses) inject their map at session start. The map is
  asked: `brief` gives a task's components in about a hundred lines, and each `ask` answers a whole round of
  questions in one call, because every call of an agent re-reads the whole conversation and the number of calls is
  what costs ([docs/EVIDENCE.md](EVIDENCE.md)).
- **A guard, not only instructions.** Instructions are context, and agents drift from them as the context grows.
  The hook refuses `grep`, `cat`, `sed` and whole-file reads on the code, and names the `ask` that answers the same
  question, in the hook formats of five agents. Among the tools above, one other refuses searches: agentmap by
  raymondchins, for high-confidence structural greps in Cursor and Codex, never in Claude Code. Cursor's blocking
  of ignored files has a different aim.
- **Nothing to host.** One program per language (Python, Node, Go or Rust), no server, no index to build or host,
  no language server, no grammar. It works on any language with a comment form.
- **It measures itself on real sessions.** `map-sessions.py` reads the agent's transcripts and says, per session,
  how many calls only read, how many went through the map, the questions per call, and the model's response time
  under and over 300k tokens of context. agentmap by raymondchins publishes a benchmark on one repository, with
  tokens estimated from characters.

## What the map lacks

- **Symbol-level relations.** The relations between components come from imports, resolved per language by
  path. A language server (Serena) or a parser (Aider, Repomix's compress) sees calls, references and types the
  map does not. In the repository the map was born in, a reader built on ESLint's parser adds that for its
  JavaScript (which block uses which module, who writes each part of the project's file, the page's events); it is
  specific to that codebase and not part of this tool.
- **No semantic search.** `brief` ranks components by the words of their ids, purposes, files and declarations
  (rarer words weigh more). It finds what the tags name; Copilot's index or an embedding search finds what the
  tags do not.
- **Tagging is work.** A codebase has to be tagged once, and kept tagged. In the codebase the map was born in, about 1,700 blocks in 170 files
  were tagged in a day by twelve agents working on separate files, and CI has kept them since; smaller
  repositories take an afternoon with one agent ([docs/TAGGING.md](TAGGING.md)). A generated map costs nothing
  to start and says less.
- **The guard sees shell commands and the agents' reading tools.** A read hidden in a program the agent writes and
  runs by name is seen when the program only prints a file; one that computes is not, by design.

## A research note

A paper at ISSTA 2026 ([arXiv 2606.26979](https://arxiv.org/abs/2606.26979)) injects "stable structural facts" as
plain-text comments into code before giving it to an agent, generated by static analysis, and reports that these
anchors roughly halve the run-to-run variance of the agent at about 10% more input tokens. The map's tags are
anchors of the same kind, written for meaning rather than structure; the paper is the nearest measurement of the
effect of comments an agent navigates by that we found.
