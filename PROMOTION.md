# Sharing the work

The texts below follow the rules of each place they go, and the tone of the article: what was measured, how, and
its limits. None of them asks anyone to install anything. Replace `<medium-url>` once the article is published.

## 1. The repository on GitHub

- **About → Description:** A code map and a pre-tool hook for AI coding agents: tags say what each block is for,
  and the agent asks the map in rounds instead of grepping. Claude Code, Codex, Cursor, Copilot, Gemini CLI.
- **About → Website:** `https://mars1571.github.io/grepless/`
- **About → Topics** (GitHub allows 20): `ai-agents`, `ai-coding`, `coding-agents`, `claude-code`, `openai-codex`,
  `cursor`, `github-copilot`, `gemini-cli`, `agents-md`, `code-map`, `codebase-navigation`, `context-engineering`,
  `context-window`, `llm`, `llm-tools`, `token-optimization`, `prompt-caching`, `developer-tools`, `pre-tool-hook`,
  `grep`.
- **Settings → General → Social preview:** upload `article/images/social-preview.png` (1280×640, under 1 MB as
  GitHub asks).
- **Settings → Pages → Source:** GitHub Actions. The `pages` workflow then publishes `site/` with the article's
  images and `llms.txt`.
- **Releases:** attach the Go and Rust binaries for macOS, Linux and Windows; `install.sh` points people there
  when they have no Go or Rust toolchain.
- **Search Console:** add a URL-prefix property for `https://mars1571.github.io/grepless/`, verify it with the
  HTML tag (paste it where `site/index.html` says), and submit `sitemap.xml`. A project site cannot have its own
  `robots.txt`, which only works at the root of the host.

## 3. Hacker News

Show HN is for things people can try, not for articles, so the tool goes as a Show HN and the article, if at all,
as a plain link on another day.

**Show HN.** Title: `Show HN: Grepless – a code map coding agents query instead of grepping`. URL: the repository.
Text:

> I kept the transcripts of 113 Claude Code sessions. 98.7% of the 10.7 billion tokens were context the model had
> already been sent, and half of what 23 agents re-read on one day was code they had looked up with grep and cat.
>
> Grepless is what I built in response: a one-line tag above each block says what it is for, a small tool builds
> a map from the tags and the code, the agent asks the map a round of questions per call, and a pre-tool hook
> refuses grep, cat and sed on the code (Claude Code, Codex, Cursor, Copilot, Gemini CLI). Python, Node, Go and
> Rust versions give the same answers.
>
> With instructions alone, the median session sent 10% of its code reads through the map; with the hook, 85%.
> That is four sessions on different tasks, with other changes made the same day, so an observation, not an
> experiment. The savings I quote come from
> replaying one session, and on the reads agents actually made, the map's answers were 36% longer: the saving is
> in calls, not answer size. Data, scripts and caveats are in the repository; the transcript script runs on your
> own sessions.

**The article, as a link** (another day): its title as it is, `Almost every token my coding agent used was a
re-read`, and the Medium URL.

## 4. Reddit

Each subreddit has its own rules on self-promotion; read them first. Where they allow it, lead with the
measurement, not the tool. For example, in a Claude Code community:

> **I measured where my Claude Code sessions' tokens went (113 sessions, data and scripts included)**
>
> 98.7% of 10.7B tokens were cache reads, context already sent. At list prices re-reading was ~60% of the cost;
> the agents' own output was 0.3% of the tokens. Response time tripled from under 100k to 700k–900k of context (about 1.8×
> for short replies alone). Half of what 23 sub-agents re-read was grep/sed/cat output and whole files. The
> write-up, with methods and limits: <medium-url>. The script that measures your own transcripts is in the repo.
